# Personal gym setup

Branch `agent/personal-gyms` stacks on weekly progress PR #11. Profile supports up to ten named gym setups, equipment editing and selecting one gym (or none). No location permissions or addresses are requested. Workouts show the selected gym and per-exercise machine settings, free-text notes and an optional preferred catalog alternative. Known exercise-name aliases share notes within that gym; notes remain separate between gyms and accounts. The current selection is a preference, not a historical record of where each workout took place. UI supports add/edit/switch, without deleting saved setups.

Gym is packed starts with selected gym equipment when available. Users can change to any equipment or another filter. A stored preferred alternative is highlighted and ordered first only when it is a valid same-muscle/type candidate and not already used. It is never selected or applied automatically. Unknown custom moves still require choosing the muscle. An empty equipment list means no saved restriction, not a claim that no equipment exists.

Migration 12 adds `gym_locations` and `gym_exercise_notes`, both protected by owner/nested RLS. An atomic invoker selection RPC locks the profile, validates ownership and enforces one selected gym. Location/note saves check reviewed update timestamps; concurrent note creation cannot overwrite an earlier save. Text limits are enforced in UI/server/database. Preferences use bundled catalog IDs and text is rendered as text. Gym selection applies on the next workout page load, with no realtime push. Missing service data shows unavailable feedback.

Verification: nine training tests (including canonical note keys and bounded equipment), local SQL equipment/selection persistence, per-gym notes, stale update rejection, malformed equipment, two-user/anonymous denial and concurrent note creation. Actual components in a synthetic cookie fixture verify adding a gym, saving settings/notes/preference, switching gyms, reload persistence, matching preferred swap display without auto-selection, and five expanded-form widths (320/390/768/1024/1440). No horizontal overflow or browser warning/error logs. Screenshot personal-gyms-phone.png is synthetic; fixture removed before final checks.

Staging checklist: apply migrations 1–12, create two test accounts with separate gym/notes, save/reload/switch, exercise alias behavior, unavailable equipment, stale tabs and real iPhone form/keyboard checks. No production data/schema/deployment changes were performed.
