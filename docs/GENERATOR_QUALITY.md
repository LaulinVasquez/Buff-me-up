# Generator validation and automated quality

The existing generator now rejects fractional/out-of-range day counts, invalid selections/experience/seed and missing selected-muscle coverage. It deduplicates catalog IDs/names, caps exercises to the experience target, rotates broad target groups and includes requested core work in suitable splits. With the bundled catalog, 3/4/5/6-day schedules at every experience are deterministic and populated. Sparse single-muscle pools may reuse an exercise across days, without duplicating it inside a day; a missing requested muscle gives an actionable error instead of an empty day.

Shared unknown-input validation protects edited plans: 3–6 days, 1–7 unique exercises/day, integer sets 1–10, nonempty bounded names/IDs/reps and supported muscles. UI disables invalid save, labels selected controls and prevents repeat submits while saving. Server action revalidates independently. Migration 13 replaces only the generated-plan save function, rejecting empty days and duplicate/malformed exercise records atomically; a failure leaves the previous active plan and stored plan count unchanged. Existing generated plans are not rewritten.

Four generator tests cover 12 day/experience combinations, selected-muscle coverage, deterministic output, sparse/duplicate pools, invalid day counts and edited empty/duplicate/fractional plans. SQL verifies four populated saved days, rollback and isolation. Actual component fixture verifies four-day generation, fractional/empty-day save blocking, regeneration recovery, actionable empty-catalog error and five generated-plan widths without horizontal overflow or console warnings/errors. It never submitted the real application save action or used production accounts; saved-plan acceptance is local SQL, not signed-in staging.

`npm test` runs training, generator, History, swaps and appearance (38 tests). `npm run check` runs lint → production build → typecheck → pure tests → disposable PostgreSQL suite. Never run build/typecheck concurrently against shared Next generated types. Database tests create their own local socket-only cluster and do not read application database credentials.

GitHub `.github/workflows/quality.yml` runs the same command on PRs and main/agent pushes, using Node 22/Ubuntu 24.04, PostgreSQL tools and loopback placeholder service URLs. Checkout/setup-node are pinned to official v6 tag commit IDs verified on 2026-11-02 (https://github.com/actions/checkout and https://github.com/actions/setup-node). Token permissions are contents:read and Git credentials are not persisted. No production secrets or deployment steps. Remote CI result is recorded separately after push; a workflow file alone does not prove remote success.

Provider API contract/terms/media licensing and physical-device/native acceptance remain outside these local generator checks. No production database migration, merge or deployment performed.
