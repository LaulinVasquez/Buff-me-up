# Short and comeback sessions

Branch `agent/session-adaptations` stacks on set logging PR #9. “Adjust session” offers 15/20/30-minute planning budgets, an opt-in comeback session and restore-full-session. The review lists exactly what stays and what is set aside before explicit acceptance. It keeps the saved routine unchanged. Completed exercises and any saved set rows are always retained. Set-aside snapshots remain stored, appear in the workout and History, and can be restored before finishing; they are never counted as completed exercises. Completing an adapted session still counts one attendance and advances the normal day rotation.

The deterministic short-session rule keeps untouched exercises in plan order while they fit a rough estimate (3 minutes preparation, 2 minutes/set, 1 minute setup). At least one untouched exercise remains even if its estimate exceeds the budget; copy explicitly says the estimate may exceed available time and excludes already-started work. Comeback keeps half the untouched exercises rounded up, plus all logged/completed work. It does not change weights, prescribe loads, infer readiness or diagnose recovery. Users opt in at any time; no absence threshold forces this choice.

Migration 10 adds deferred flags and session mode/revision/history. The invoker RPC locks the owned parent and snapshots, verifies a complete reviewed timestamp set and mode revision, preserves logged work and appends adaptation history. Logs/swaps on deferred exercises are rejected until restored. Finished scope cannot change. App server recomputes the proposed scope and the DB rejects a review that became stale. No workout or template rows are deleted.
