# Flexible goals and explained progress

Branch `agent/weekly-progress` stacks on session adaptation PR #10. Profile offers an account-saved goal of 1–7 attendance days/week. Home and History show the current Monday–Sunday week in the viewer's timezone, distinct attended dates, last week's count, goal progress and one schedule-focused next step. Two workouts on the same day count once. Rest/missed days do not erase the weekly record. Primary workout/History chart controls stay ahead of the review on phones.

The set review is bounded to up to 100 latest completed sessions in the past 90 days. It compares best-set reps at the same explicit weight for the same stable exercise identity/name across the latest two sessions. It can describe a highest recorded load within this limited review, with an explicit note that reps may differ. It never calls this an all-time record or infers strength/medical readiness. Deleted custom templates, unknown identities, deferred/incomplete records, unspecified weights, invalid/future dates and old exercise-level weights do not generate comparisons. Empty data prompts actual logging. At most three recent exercise summaries are shown.

Migration 11 adds `gym_profiles.weekly_goal` with default 3 and bounds 1–7, under existing owner RLS. Validated server save authenticates the user and refreshes the app layout. Failed saves retain selection and show an error; missing data service returns an unavailable message rather than fabricated progress. Saved preferences apply on subsequent account page loads, without realtime cross-device push.

Passed eight training tests (including local week/DST boundary, duplicate-day and identity/comparison exclusions), goal SQL persistence/default/bounds/isolation and full existing SQL/concurrency regressions. Actual components in a synthetic cookie fixture verify goal save/reload, changed progress/goal met, failed-save selection retention, empty review and 320/390/768/1024/1440 widths without overflow or browser warnings/errors. No real user data. Screenshot weekly-progress-phone.png is a labeled synthetic preview. Final lint/build/typecheck outcomes are in AGENT_SESSION_LOG.md.

Before release: apply migrations 1–11 to staging; verify real authenticated goal saves, actual set changes, timezone boundaries and device behavior. No production migration/deployment was performed. All-time records and broader progression prescriptions are outside this feature.
